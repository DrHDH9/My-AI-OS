# sum/ — 摘要层

**这里放什么**：把同主题的一批记忆压成的一条归纳（`type: 摘要`）。

**什么时候填**：某个 topic 攒够 5 条（`config.json` 里 `consolidate.group_min`），就该压了。

**谁读**：
- `brief` **不直接读**（摘要也是记忆，靠 `search` 找，或靠 `type: 摘要` 筛）
- `search` 会搜这里

---

## 为什么要有这一层

**卡住记忆系统的从来不是磁盘，是 AI 的注意力。** 每次简报只能塞进 5 条 300 字——AI 一次就读得进这么多。

一天 2000 条记忆时，单条被读到概率 0.25%，轮一遍要 400 天。这时候继续加容量没有意义，**唯一有用的动作是把多条压成几条**。

## 怎么做

```bash
mem.py consolidate          # 机器挑出该压的组
# 然后 AI 读那些条目，写一条归纳
mem.py add --type 摘要 --topic <同名> --title "..." --body "稳定结论"
```

**机器只负责挑，摘要文字必须由 AI 写**（或者你自己写）。原因是摘要不可逆，压缩过程中丢掉的细节没法还原，所以这一步不能交给纯规则。

## 一条铁律

**原条目不动。** 摘要只是多了一层视图，不是替换。原文永远留着，随时能 `search` 回到底稿。

这也是这一层的价值所在：**它让"记得多"和"读得完"不再矛盾。**
