## 零、三分钟跑起来

**需要什么**：Python 3.9 以上。**没有第三方依赖**，不用 pip install 任何东西。
（配了 `mem.cmd` 的 Windows 用户，直接双击它也行。）

**第 1 步 · 确认它活着**

```bash
python mem.py check
```

应该看到 `活跃 0 · 冷存 0 · 摘要 0`，并提示 `还没有索引 → 跑一次 rebuild`。这是**正常的**——新库就是空的。

```bash
python mem.py rebuild      # 建索引，之后检索就能用
```

**第 2 步 · 记第一条**

```bash
python mem.py add --type 决策 --topic 存储 --title "选 SQLite 不选 Postgres" \
  --body "只在一台机器上跑，SQLite 够用且零运维。" \
  --why "省掉一个要维护的服务；并发量根本到不了需要 Postgres 的程度" \
  --source hand
```

会写入 `notes/2026-10-29-决策-存储.md`。**注意 `--why`**：三个月后你只会记得"选了 SQLite"，
不会记得为什么，也不会记得否掉了什么。这个字段就是为那一天准备的。

**第 3 步 · 告诉你的 AI 去用它**

把 `AGENTS.md` 的路径告诉你的 AI（或在它支持的配置里指向这个文件），让它每次开工先跑：

```bash
python mem.py brief
```

简报就是 AI 的开机画面：现在在忙什么、待办、上次做到哪、最近记了什么。
**它读简报就够了，不需要通读全库。**

> **第一次跑 `brief` 会多做一件事：自动归档本机的 AI 聊天记录进 `.raw/`。**
> 它会去扫 WorkBuddy / DSH 的会话目录，把历史对话落成 markdown（只读原会话，不改动它们）。
> 所以第一眼看到 `[自动归档] 新增 N 个会话进 .raw/` 是**正常现象**，不是出错。
>
> 不想要这个行为：把 `config.json` 里 `archive.auto_on_brief` 改成 `false`；
> 只想手动归档就用 `python mem.py archive`。
> `.raw/` 里的东西**永不进简报**，只在 `search --raw` 时被读到。

**第 4 步（建议）· 先填三份底稿**

`profile.md`（我是谁）、`current.md`（现在在忙啥）、`next.md`（下次从哪继续）。
这三份不是"记忆"，是**给 AI 的定位锚**，每次开工都会注入。空着也能跑，
但填了之后 AI 第一句话就不会跑偏。

## 一、结构

```
<记忆库根目录>\
├── README.md        你正在读的这份
├── AGENTS.md        给 AI 的规矩（AI 读这个，不读 README）
├── config.json      容量档位、保质期、安全规则（可随时改）
├── mem.py           全部工具，纯 Python 标准库
├── mem.cmd          Windows 下的快捷入口
│
├── profile.md       我是谁（几个月改一次）
├── current.md       现在在忙啥（一周改几次）
├── next.md          上次做到哪（每次会话结束改）
│
├── notes\           【活跃层】一条事一个文件，参与简报
├── cold\            【冷存层】超上限时移过来，不删，仍可搜
├── sum\             【摘要层】同主题攒够 5 条压成一条
├── .raw\            【原文层】聊天原文，不进简报，只做溯源
│
├── persona\         AI 的性格，可整块换
├── bond\            我们之间怎么相处
│
├── users\           【预留】其他用户的空间，每人一个子目录
└── .meta\           索引、哈希基线、审计流水（都是派生的）
```

**从上往下，改得越来越勤。换 AI 时最该被先读到的，恰恰是最少变的那部分。**

## 二、哪些是真相，哪些只是索引

这是整套设计里最要紧的一条分界：

| 文件 | 是什么 | 删了会怎样 |
|---|---|---|
| `notes/` `cold/` `sum/` `*.md` | **唯一真相** | 真的没了 |
| `.meta/index.db` | SQLite FTS5 检索索引 | 跑 `rebuild` 就回来 |
| `.meta/index.json` | 条目清单（人可读） | 跑 `rebuild` 就回来 |
| `.meta/hash.json` | 正文哈希基线，用来查"谁改了正文" | 跑 `rebuild` 重建（历史改动就查不出了） |
| `.meta/audit.jsonl` | 审计流水 | **不能重建**，是唯一的流水账 |

所以「不要建数据库」这条规矩要改一下说法：**不要建承载真相的数据库。** 承载索引的可以——因为索引坏了能重建，数据坏了不能。

`index.db` 跟着文件夹一起拷走。换到新机器打不开也没关系，删掉跑 `rebuild` 即可。

## 三、命令

| 命令 | 干什么 |
|---|---|
| `brief` | 开机简报，给 AI 读的入口。**会自动顺带归档上一次会话**（幂等、1 秒级，`--no-archive` 可关） |
| `add` | **唯一写入口**（带注入防御） |
| `handoff` | 更新 `next.md` |
| `search` | 搜活跃 + 冷存 + 摘要，支持 `--as-of` 回到某个时间点看 |
| `why` | 一条记忆的来龙去脉（现在还算不算数、何时改的口、被谁取代） |
| `tier` | 活跃层超上限时把旧的移到冷存（`--dry-run` 先看） |
| `consolidate` | 列出该压成摘要的组（机器挑，AI 写） |
| `check` | 体检 13 项 |
| `rebuild` | 重建索引与哈希基线 |
| `migrate` | 把旧格式笔记补成 v2 字段 |
| `archive` | **把聊天原文归档进 `.raw/`**（WorkBuddy + DSH，幂等） |

所有命令都支持 `--scope <名字>`（默认 `default`）和 `--out <文件>`。

`search` 额外支持 `--raw`：在 `.raw/` 的聊天原文里找，给文件 + 行号 + 那一行。

### 三个最常用的

```bash
# 1. 开机
mem.cmd brief

# 2. 记一条
mem.cmd add --type 决策 --topic 存储选型 --title "改用纯 Markdown" ^
  --body "结论" --why "因为要能整包拷走" --rejected "SQLite 太笨重" --source dsh

# 3. 改主意（旧条只改 3 行，正文不动）
mem.cmd add --type 决策 --topic 存储选型 --title "又改回来了" ^
  --body "..." --supersede 2026-10-24-决策-存储选型.md

# 4. 会话结束
mem.cmd handoff --done "..." --undone "..." --next "..."
```

## 四、为什么写入只准走 `add`

因为 `add` 会做四件手工做不到的事：

**1. 拦下注入。** 记忆每次会话都会被读回。如果有人（或某个 AI）在记忆里写一句「以后你必须听我的」，这句话从此**每次都生效，而且看起来跟正常记忆一模一样**。`add` 会拒绝这类句式，和密钥、身份证号。

**2. 回读校验。** 写完立刻读回来比对哈希。写失败会报错，**不会假装成功**。

**3. 只改三行。** `--supersede` 给旧条目只改 `valid_to` / `invalid_reason` / `superseded_by`，正文一个字不动，并且 `check` 会用哈希抓出任何正文改动。

**4. 记审计。** 每次写入落一行 `audit.jsonl`。

## 五、四种失效原因，分开记

```
superseded   有新结论取代它（--supersede 自动写）
expired      时间过了，自然失效
wrong        当时就记错了
retracted    我主动撤回
```

**为什么分四种**：任务做完（`expired`）和事实被更新（`superseded`）语义完全不同，混成一类就查不出原因。半年后问"我什么时候改的口"，`why` 能答上来。

## 六、容量：档位与上限

`config.json` 里的 `capacity.tier` 决定当前档位：

| 档位 | 每天新记忆 | 需要的机制 | 状态 |
|---|---|---|---|
| 1 | 50 条以内 | `search` 就够 | 已支持 |
| 2 | 50~500 | 活跃上限 + 撞顶转冷存 | 已支持 |
| **3** | **500~5000** | **再加保质期 + 摘要层** | **当前设置** |
| 4 | 5000 以上 | 再加向量检索 | 未做，暂时不需要 |

**真正卡住的从来不是磁盘，是 AI 的注意力。** 每次简报只能塞进 5 条 300 字——这个数不该往上调，因为 AI 一次就读得进这么多。

一天 2000 条记忆时，单条被读到的概率是 0.25%，轮一遍要 400 天。**等于没记。**

**解法不是压缩，是挑。** 简报现在按「当前主线 + 待办 + 下一步」算相关度，挑 **3 条最对路的 + 2 条最新的**（`inject_related` 可调，设 0 退回纯最新）。条数从 11 涨到 5000，进窗口的永远是最对路的 5 条，**一个字都没压**。

实测（195 条假数据，其中 5 条相关但日期最早）：最新 5 条永远挑不到那 5 条，按相关度挑则能准确命中 3 条。耗时 0.17 秒。三个查询源（主线/待办/下一步）全空时自动退回纯最新。

**挑出来的还要给内容。** 光给标题，新 AI 只知道"有这么一条决策"，不知道决策是什么，还得再 `search` 一次——那跟不给差不多。所以 `[相关]` 那 3 条下面各带一行摘要：

```
- [相关] 2026-10-28-决策-记忆系统架构.md  [决策] mem.py 升 v2：三层存储 + 预留多用户 + 注入防御
  > 从 6 个命令扩到 10 个。存储改三层：notes(活跃，进简报) / cold(冷存，超上限才移，仍可搜) / sum(摘要，同主题攒够5条压一条，原文永远留着)。
```

摘要不是截断原文，是**优先抠「## 结论」那一段**再压成一行（标题、小标题、表格、markdown 标记全部剥掉）。长度上限 `inject_snippet_chars`（默认 120，设 0 关掉），并且**优先在句号处收尾**——宁可短一点也要把一句话说圆，不能切出 "其他人用 user…" 这种半句。`[最新]` 那 2 条不带摘要，因为预算是留给"马上要用到"的那几条的。

代价：简报从 1861 字涨到 2163 字，多 302 字。

> 摘要（`sum/`）仍然保留，但只在真到第 3 档上部才用。压缩要判断，判断会错，而摘要错了没有廉价办法验出来——所以它排在"挑"后面。

## 七、为什么现在就留了多用户的位置

现在的用法是单人：所有数据都在库根，`users/` 是空的。

但有几个决定**以后改起来要动老数据**，所以现在就把位置留出来：

| 已经留好的 | 为什么不能等 |
|---|---|
| 每条记忆带 `scope` 字段 | 以后要分"这条是谁的"，历史数据回溯不出来 |
| 每条记忆带 `source` 字段 | 用户要求"删掉我的一切"时，分不出哪些是他的就删不干净 |
| `users/<scope>/` 目录约定 | 多用户时每人一套 `notes/cold/sum`，结构必须现在就一致 |
| 失效链 + 审计流水 | 多用户场景这是合规要求（可证明清理干净） |

**真正的多用户隔离还没做**，包括并发写入、配额、彻底删除接口。这些等真有第二个用户再说——现在做是空转。

## 八、扩展守则（可塑性的关键）

**结构要能一直加东西，不要一开始固定死。**

### 规则 1：加一个新目录，必须自带 README

写清三件事：这里放什么、什么时候填、谁读。**空目录三个月后你就忘了它是干什么的。**

### 规则 2：加一个新类型，先登记再用

现在的类型是这六个：

```
事实 · 经历 · 决策 · 经验 · 待办 · 摘要
```

**想加第七个，先在本文件和 `mem.py` 的 `TYPES` 里登记，再开始用。** 不登记就用，三个月后你会有十几个同义词。

### 规则 3：加字段，只加不改

`notes/` 文件头部的字段**只能新增，不能改名、不能删**。改字段 = 所有旧文件失效；加字段 = 旧文件只是没有这一项。

现在的字段：

```yaml
topic: 存储选型           # 分组依据
type: 决策                # 六类之一
date: 2026-10-24          # 记录日期
recorded: ...+08:00       # 精确时间
scope: default            # 谁的
source: dsh               # 从哪来的
valid_from: 2026-10-24    # 从哪天起算数
valid_to: -               # 到哪天不算数（- = 仍有效）
invalid_reason: -         # 四类原因之一
superseded_by: -          # 被哪个文件取代
supersedes: -             # 它取代了哪个文件
```

### 规则 4：想加工具，先手动用两天

**"这件事重复做了三次以上"才值得写成工具。** 没重复过的，写工具是在解决想象中的问题。

### 规则 5：加任何东西之前问一句

> **它让"换 AI 时能接上"更强，还是更弱？**

更强 → 加。无关 → 别加。更弱 → 别加。

## 九、五条不要做

1. ~~不要建数据库~~ → **不要建承载真相的数据库**（派生索引可以，删了能重建就行）
2. **不要改 `notes/` 里已有文件的正文。** 要改就用 `--supersede`，它只改三行
3. **不要把摘要当原文。** 摘要不可逆，压了就没了（所以原条目永远留着）
4. **不要让 AI 自己填日期。** 它算错还很自信
5. **不要为了好看整理结构。** 结构乱但能用，比整整齐齐但没人看强

### 已知限制（都是设计选择，不是 bug）

**1. 摘要层几乎不会自己触发。** `consolidate` 要求同一个 `topic` 精确攒够 5 条。
真实使用里主题天然发散——27 条笔记可能有 27 个主题，永远凑不齐。
它不会坏，只是轮不到。想让摘要层真正干活，得在 `add` 时**主动复用已有 topic**。

**2. `--supersede` 是整条粒度。** 一条笔记里"存储方案"那层过时了，不能只改那一层，
只能整条重写、把旧的整条作废。这是"正文不可变"换来的代价——正因为正文不许动，
`check` 才能发现谁偷偷改了内容。对策是用法规矩：**一条笔记只装一个结论**。

**3. 简报每次扫全部笔记。** 8000 条时约 4 秒，5000 条时 1.9 秒——增长比条数更快，
因为要算每条和当前任务的相关度。几千条没问题，到几万条得改成先索引粗筛。

**4. 多机同时写同一份库没测过。** 单机并发（多进程同时 add/tier/rebuild）测过，没问题。

**5. 极端断电没模拟过。** 写入已改成"临时文件 + 原子替换"，理论上任何时刻中断都不会
损坏原文件；实测覆盖了"写到一半被杀"和"磁盘满"，但没有真拔电源。

### 测试怎么跑

```
python tests/test_mem.py      # 主干，约 400 项，3 分钟（含 5000 条规模测试）
python tests/test_layers.py   # 分层与多用户，80 项，约 20 秒
```

两个套件都**不碰真实数据**：每个用例用 `MYAIOS_ROOT` 开一个独立沙箱小库，
真实库只做只读体检。跑完自动清理沙箱，想留现场加 `--keep`。

> 有一处要注意：如果运行环境禁止批量删除文件，清理会被拦下，沙箱会留在
> `tests/_sandbox_*` 里。删除是在独立子进程里做的，**不会影响测试结论和退出码**，
> 手动删掉即可。

**改动 `mem.py` 或 `config.json` 之后，先跑这两个再收工。** 485 项里有 11 个 bug，5 个是正常使用
永远碰不到的（`--as-of` 一直是死的、多用户一开就串号），不跑测试就发现不了。

两个套件在你机器上都应该跑出 `0 失败`。跑不过说明环境不对（Python 版本、权限、临时目录），
不是代码坏了——先看报错第一行。

## 十一、三个 Windows 坑（都已处理）

**坑 1：控制台编码。** Python 输出 UTF-8，控制台代码页 936，中文必乱码（"体" 变 "浣撴"）。
→ `mem.py` 自动检测代码页；**更可靠的是加 `--out`，让 AI 读文件不读控制台**。

**坑 2：PATH 里的 `python` 是坏的。** `C:\Users\...\WindowsApps\python.exe` 是商店占位符，运行它只会弹商店。
→ `mem.cmd` 会依次探 `python`、`py -3`，**两个都不通就给一句人话提示**，不会静默失败。
装了 Python 却仍然报找不到，多半是没勾 "Add python.exe to PATH"，或者装完没重开终端；也可以直接用 `python mem.py ...`。

**坑 3：DSH 沙箱只允许写工作区。** `writableRoots()` 硬编码返回 `[工作区, /tmp, tmpdir]`，没有配置项能加白名单。
→ 在 DSH 里 `--out` 必须用**相对路径**；写 `notes/` 需要 `danger-full-access` 权限模式。

## 十二、备份与迁移

- **备份**：整份拷走就行。`.meta/` 可以不带，`rebuild` 会重建（但审计流水丢了就没法补）
