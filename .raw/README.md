# .raw/ —— 聊天原文归档

> **新装时是空的。** 跑一次 `mem.py archive` 就会填上。
> 这个目录以点开头，**默认不进简报、不进上下文、不参与淘汰**（这是刻意的）。

## 里面是什么

```
.raw/
├── 2026-08/
├── 2026-09/
└── 2026-10/
    └── 2026-10-22-workbuddy-<项目名>-36bafb3e.md
```

一个会话一个文件，文件名 = `<开始日期>-<平台>-<项目或工作区>-<会话ID前8位>.md`。
按月分子目录。

## 怎么来的

```
python mem.py archive               归档全部（WorkBuddy + DSH）
python mem.py archive --only wb     只归档 WorkBuddy
python mem.py archive --only dsh    只归档 DSH
python mem.py archive --force       源没变也重导
```

`mem.py brief` 每次开工也会**顺带跑一次归档**（6 小时间隔内不重复跑，`--no-archive` 可关）。

**源在哪里：**

| 平台 | 原始位置 | 格式 |
|---|---|---|
| WorkBuddy | `%USERPROFILE%\.workbuddy\projects\<项目>\*.jsonl` | 明文 JSONL |
| DSH | `<DSH 安装目录>\sessions\<工作区>\session-<uuid>\session.v4.jsonl.zstd` | 多帧 zstd |

**你用的不是这两个工具？** 那就什么都不用做——`.raw/` 一直空着，**其它功能完全不受影响**。
想用溯源功能的话，把原话手动存进来（markdown / txt 都行），`search --raw` 一样能查到。

DSH 的 `.zstd` 文件 Python 标准库解不了（3.13 没有 zstd 模块），脚本会调 `node`
走 `.tools/zstd2jsonl.js` 按魔数逐帧解压。**没装 node 也不影响 WorkBuddy 侧的归档**，
DSH 侧会跳过并说明原因。

## 存的是什么，剥的是什么

**存：** 用户说的每一句话（原样，不筛寒暄、不砍长消息）+ AI 的每一条回复。

**剥：** 只剥机器塞给 AI 的东西 —— `system-reminder` 注入块（当前时间、记忆提醒、工作区身份文件）、工具调用与工具返回、模型内部推理。

判断标准很简单：
> **人和 AI 说的话，一个字都不删；机器自动填的上下文，全部剥掉。**

## 为什么 AI 不读它

**原文是证据，不是上下文。**

把整段对话塞进窗口，既贵又吵。原文的用途是：三个月后你想确认"当时到底怎么说的"。

所以检索是**按需的**：

```
python mem.py search --raw <关键词>
```

它会给出文件 + 行号 + 那一行原文。不带 `--raw` 搜的是结论（`notes/`）。

## 三条硬规则

1. **不要用摘要替换原文。** 摘要不可逆——"当时为什么否掉另外两个方案"这种最值钱的东西，压两句话就没了。
2. **归档独立于淘汰。** `tier` 只动 `notes/` 和 `cold/`，**永远不会碰这里**。清理活跃记忆和保留历史证据是两件事。
3. **重复导入幂等。** 源文件没变就跳过；会话还在增长时会整份重写（记 `source_bytes` / `source_mtime` 判断）。
